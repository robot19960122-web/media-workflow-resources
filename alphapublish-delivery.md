# Transparent web video: test delivery, not only the mask

Prepared for AlphaPublish with AI assistance. This is a practical acceptance checklist, not a compatibility certification.

## Separate three decisions

1. **Transparency:** does the approved moving result preserve the desired subject edges?
2. **Packaging:** does the delivered format contain the expected transparency and dimensions?
3. **Website delivery:** does the actual published page remain useful when animation cannot play?

A file opening successfully in an editor does not prove alpha playback in every browser. A codec label alone also does not establish that visible transparency is present. Review against light, dark and patterned surfaces and through the full movement, not only the first frame.

## Make the published page the acceptance target

Reserve explicit space for the component. Inspect cropping, overflow, stacking and behavior at the real layout breakpoints. Test the public URL rather than relying on an editor preview. Recheck when a delivery asset is replaced, including the poster and any old cached destination page.

Record each scenario separately:

| --- | --- | --- |

Untested devices remain unverified. Do not describe a desktop browser check as an iPhone or Android result. Keep versions and file checks distinct from real playback evidence.
